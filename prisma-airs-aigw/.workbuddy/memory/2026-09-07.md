# 2026-09-07

## prisma-airs-aigw：Dify UI 检测不到运行时生成的模型 YAML —— 根因诊断

- Dify 插件(SDK 0.9.x)的模型列表机制：启动时解析 `provider/prisma-airs-aigw.yaml`，其 `models.llm.predefined` glob(`models/llm/*.yaml`)在进程启动瞬间被展开并解析为 AIModelEntity，随 `MODEL_DECLARATION` 一次性上报 Plugin Daemon；UI 模型列表只读这份启动快照（见 dify_plugin/entities/model/provider.py 的 ProviderEntity.validate_models、plugin.py `_initialize_tcp_stream`）。启动后新写 YAML 不会触发重新上报。
- 本项目把“拉取网关 /models 并写 YAML”放在 `validate_provider_credentials`（保存凭证时）→ 必然发生在声明上报之后；随后 `os._exit(0)` 想靠重启重新声明：远程调试模式(INSTALL_METHOD=remote)下无人拉起进程；打包安装模式下 models/llm 在 .difypkg 内只有 .gitkeep+llm.py（已验证），容器内运行期文件易失。结果 UI 始终 0 个预定义模型。
- `predefined_models()` override 只影响运行期 RPC(按模型名取 schema/invoke)，不影响 UI 列表。
- 修复方向：走官方静态声明 —— 打包前先跑一遍 write_model_yamls 把 YAML 打进 difypkg 再安装/升级；或改用 customizable-model 流程（get_customizable_model_schema 已实现）让用户在 UI 手动填模型名。

## 续：能否“hold 住上报、输 key 后再上报”？—— 不能（SDK 0.9.x 源码定论）

- `PluginRegistration` 在 `Plugin.__init__` 一次构建并缓存 `models_configuration`（glob 展开 YAML 的唯一时机），后续每次建连 `_initialize_tcp_stream` 重发的是**同一份缓存**（plugin.py:128-136）。
- TCP 断线会自动重连(3 次/5s)并重发 MODEL_DECLARATION，但内容是启动快照，**不会重新 glob**（request_reader.py `_connect`→`on_connected`）。→ 只关 socket 没用，`os._exit` 远程调试无人拉起，均不可行。
- 想重读新 YAML 只有**进程整体重启**这一条通道（重新执行 PluginRegistration）。且“首次声明前 UI 无凭证表单”，架构上不可能“等到输 key 再首报”。
- 推荐落地：provider yaml 已含 `configurate_methods: [predefined-model, customizable-model]` + llm.py:363 `get_customizable_model_schema` 已实现 → 走 **customizable-model 主路径**：key 校验后拿该环境 /models，用 Dify Console API 批量 add 为 custom model（模型存 Dify DB，天然按环境隔离），UI 立即可选，无需重打包/重启。批量 add 时字段需与 get_customizable_model_schema 对齐。
